# MOTUS — формулы

Вся математика системы. Реализация: `motus/core.py`, `motus/gates.py`, `motus/budget.py`.
Обозначения: `Δt` — шаг в секундах, `x_i` — драйв i, `clip(v,a,b)` — ограничение.

**Главный инвариант всех формул:** динамика выражена через `exp(−Δt/τ)`, а не через
вычитание константы за тик. Отсюда точная композируемость: `tick(60) ≡ 6 × tick(10)`.
Это то, что позволяет замедлять heartbeat во сне без всякой компенсации. Тест
`test_dt_invariance` проверяет это на каждом коммите.

---

## 1. Часы

### 1.1 Циркадный ритм

```
h(t)          = локальный час с дробной частью ∈ [0,24)
energy_circ   = 0.5 + A_c · cos(2π · (h(t) − φ) / 24)
energy        = clip(w_c · energy_circ + (1 − w_c) · energy_sensor, 0, 1)
```

`A_c` — амплитуда (0.18), `φ` — час пика (15:00), `w_c` — вес ритма против датчика (0.6).

### 1.2 Тишина и свежесть контекста

```
T_sil  = t − t_last_contact          время с последнего контакта
T_ctx  = t − t_last_context          возраст контекста
F      = exp(−T_ctx / τ_ctx)         свежесть ∈ (0,1]
```

Полосы свежести (границы по F и соответствующий возраст при τ_ctx = 6 ч):

| Полоса | F | возраст | эффект |
|---|---|---|---|
| `fresh` | > 0.70 | < 2.1 ч | ссылаться на контекст можно |
| `aging` | 0.30…0.70 | 2.1…7.2 ч | ссылаться с оговоркой |
| `stale` | 0.05…0.30 | 7.2…18 ч | требуется переспросить |
| `expired` | < 0.05 | > 18 ч | **гейт**: ссылаться как на актуальное запрещено |

`expired` — не подсказка модели, а запрет в capability mask.

### 1.3 Субъективное время (опционально, по умолчанию выключено)

```
Δt_subj = Δt · (1 + k_subj · A)
```

При высокой активации ожидание тянется дольше. Влияет только на формулировки
вербализатора, не на ядро.

## 2. Эффективный сетпоинт

```
s_i^eff = clip(s_i^base + Σ_k c_ik · u_k(t), 0, 1)
```

Контекстные слагаемые (единственные четыре):

```
PANIC:    u = (T_sil − G) / τ_sep
          s^eff = P_max · u · exp(1 − u)                при u > 0, иначе 0

SEEKING:  b = B_max · (1 − exp(−(T_idle − G_b) / τ_b))  при T_idle > G_b, иначе 0
          s^eff = s^base · (0.5 + 0.5 · energy) + b

PLAY:     s^eff = s^base · energy · (1 − max_aversive)
```

где `max_aversive = max(FEAR, RAGE, PANIC)`, `G` = 1 ч, `τ_sep` = 4 ч, `P_max` = 0.75;
`G_b` = 2 ч, `τ_b` = 6 ч, `B_max` = 0.35.

Динамический сетпоинт позволяет описать и сепарацию, и скуку **той же самой** формулой
релаксации, без отдельного механизма накачки.

**PANIC — альфа-функция, а не монотонный рост.** Она достигает максимума `P_max` ровно
через `G + τ_sep` после последнего контакта и дальше спадает. Это протест → отчаяние →
отстранение по Панксеппу, и это же чинит инженерную проблему: монотонный вариант
защёлкивал PANIC навсегда, а поскольку у него приоритет выше, чем у аппетитивных
драйвов, он монополизировал режим на всё время отсутствия человека — то есть на
большую часть суток. Аппетитивные драйвы при этом были недостижимы в принципе
(проверено прогоном).

**Скука** решает зеркальную проблему: тонический сетпоинт SEEKING (0.35) лежит ниже
его порога (0.62), поэтому без внешней стимуляции режим SEEKING не наступал никогда.
Слагаемое скуки поднимает сетпоинт при долгом отсутствии нового входа, и система
переходит к исследованию сама.

PLAY гасится любым активным аверсивным драйвом — прямо из теории Панксеппа: игровое
поведение подавляется при активации аверсивных систем. Животное не играет, когда
страшно.

## 3. Релаксация драйва

```
τ_i^eff = τ_i / clip(1 + k_ne·(ne − ne₀) + k_5ht·(ht5 − ht5₀)·[i аверсивный], 0.25, 4.0)

x_i ← s_i^eff + (x_i − s_i^eff) · exp(−Δt / τ_i^eff)
```

`ne` ускоряет всю динамику; `ht5` ускоряет **только** спад аверсивных (терпимость =
быстрое восстановление после испуга). Знаменатель ограничен, чтобы модуляторы не могли
выродить τ в ноль или бесконечность.

Композируемость точна при постоянных `s^eff` и `τ^eff` на интервале. При меняющихся
входах — приближённа, ошибка порядка O(Δt²·|ds/dt|); поэтому тик ограничен сверху
(`tick_max_s` = 600 с).

---

## 4. Импульс с насыщением

```
m_i      = 1 + k_da·(da − da₀)                             для SEEKING, CARE, PLAY
m_i      = 1 + k_ne·(ne − ne₀) − k_5ht·(ht5 − ht5₀)        для FEAR, RAGE, PANIC
m_i      ← clip(m_i, 0.2, 2.0)

h(key)   = exp(−n_key / κ)                                  габитуация
Δ        = a · g_i · m_i · h(key)                           a ∈ [−1,1] — амплитуда события

x_i ← x_i + Δ · (1 − x_i)      при Δ > 0
x_i ← x_i + Δ · x_i            при Δ < 0
```

Двустороннее насыщение: у границ приращение стремится к нулю, `x` не покидает [0,1]
никогда — не clip'ом, а по построению. Это важнее, чем кажется: clip прячет
переполнение, насыщение его не допускает.

### Габитуация

```
на импульс:  n_key ← n_key + 1
на тик:      n_key ← n_key · exp(−Δt / τ_hab)
```

κ = 3.0, τ_hab = 90 мин. Ключ формируется как `<источник>` или `<template_id>` —
второе обязательно, иначе система залипнет на любимом шаблоне.

---

## 5. Активация

```
A = clip(a₀ + k_A,ne·(ne − ne₀) + k_A,ph·max_aversive − k_A,en·(1 − energy), 0, 1)
```

Усталость **снижает** активацию, а не повышает: низкая энергия — это не тревога.
Величина производная, нигде не хранится.

---

## 6. Пороги и выбор режима

```
shift        = k_θ,5ht·(ht5 − ht5₀) − k_θ,da·(da − da₀)
θ_hi,i^eff   = clip(θ_hi,i + shift, 0.05, 0.98)
θ_lo,i^eff   = min(θ_lo,i + shift, θ_hi,i^eff − 0.05)
```

Более высокий `ht5` — выше пороги — система дольше терпит; более высокий `da` — ниже
пороги — быстрее переходит к действию.

### Гистерезисная защёлка

```
active_i:  False → True   при  x_i ≥ θ_hi,i^eff
           True  → False  при  x_i <  θ_lo,i^eff
```

### Победитель

```
кандидаты = { i : active_i }
ключ(i)   = (priority_i, x_i / θ_hi,i^eff)
winner    = argmax по ключу лексикографически
regime    = winner, если кандидаты непусты, иначе "baseline"
```

Приоритеты: FEAR = RAGE = 5, PANIC = 4, CARE = 3, SEEKING = 2, PLAY = 1.

### Dwell

```
смена режима разрешена, если   (t − regime_since) ≥ D
                          или   priority(кандидат) > priority(текущий)
```

D = 180 с. Второе условие — намеренный override: аверсивный драйв прерывает что угодно
немедленно.

## 7. Бюджет инициаций

```
на тик:       b ← min(B, b + r · Δt)                    leaky bucket
инициация разрешена, если:
              b ≥ 1
        и     (t − t_last_init) ≥ R                     рефрактерный период
        и     не висит неотвеченная инициация
        и     gate.may_initiate
        и     a_dominant ≥ θ_act^eff,   где a = x / θ_hi^eff  (нормированная активация)
при инициации: b ← b − 1,  t_last_init ← t
```

B = 3, r = 1/3600 с⁻¹ (одна инициация в час), R = 1200 с. Повторная инициация запрещена, пока висит неотвеченная.

### Штраф за молчание

```
инициация без ответа:  p ← min(p + δ, p_max)
на тик:                p ← p · exp(−Δt / τ_p)
θ_act^eff            = θ_act + p
```

```
возвращение пользователя:  p ← p / 2
```

δ = 0.15, p_max = 0.60, τ_p = 24 ч. **Знак принципиален:** неотвеченное сообщение
повышает порог следующего. Это единственное, что отличает систему от спам-бота.

τ_p намеренно велик, а прощение привязано к возвращению человека, а не к времени:
иначе штраф рассасывается ровно с той же скоростью, с какой копится, система находит
равновесие и продолжает писать вечно (проверено на прогоне: без этого выходит
одно сообщение в полтора часа бесконечно).

Порог инициации Tier 2 сравнивается с **нормированной** активацией `a = x / θ_hi^eff`,
а не с сырым драйвом: пороги у драйвов разные, сырые значения несравнимы.
θ_task = 1.00 (на уровне порога режима), θ_act = 1.25 (на четверть выше).

## 8. Адаптивный интервал тиков

```
Δt_next = clip(Δt_min + (Δt_max − Δt_min) · (1 − A)^γ, Δt_min, Δt_max)
```

Δt_min = 45 с, Δt_max = 600 с, γ = 2. При открытой задаче или свежем событии
принудительно Δt_min. Это и есть «сон»: при низкой активации система тикает раз в
10 минут, и математика от этого не страдает.

---

## 9. Консумация

```
верифицированная:    Δx_i = −ρ_full · x_i        ρ_full = 0.55
неверифицированная:  Δx_i = −ρ_part · x_i        ρ_part = 0.15
                     + габитуация ключа "unverified:<template_id>"
```

Насыщение **пропорционально текущему уровню**: чем сильнее хотелось, тем больше
утоление в абсолюте, но полностью в ноль один акт не гасит.

### Новизна как критерий (SEEKING)

```
novelty = 1 − max_j cos(e_new, e_j)          по корпусу памяти
консумация засчитывается при novelty ≥ θ_nov = 0.35
```

Полностью в коде, модель на неё не влияет. Пересказ уже известного насыщения не даёт.

## 9.1. Выбор шаблона и насыщение репертуаром

```
score(T) = h("template:" + T.id) · (0.5 + 0.5 · prior(T))
prior(T) = 0.5                          при n_T < 3   (мало измерений — не решаем по ним)
         = clip(2 · E_T, 0, 1)          иначе

задача выдаётся, если  max_T score(T) ≥ score_min = 0.30
```

Габитуация здесь не только переставляет шаблоны местами, но и **запрещает брать
задачу вообще**. Без этого порога единственный шаблон драйва крутится бесконечно —
тот же аттракторный коллапс, только в поведении, а не в тексте.

Протухшая невыполненной задача наказывает свой шаблон:

```
при истечении TTL:  n_key ← n_key + 2.0
```

Задача, которую никто не выполнил, — свидетельство, что исполнитель сломан или шаблон
нереализуем. Правильный ответ — перестать её ставить, а не ставить чаще. Без этого
правила прогон с неработающим исполнителем даёт двести одинаковых задач за трое суток
(проверено).

Дополнительные ограничители: интервал между выдачами `task_min_interval_s` = 600 с,
длина очереди ≤ 3, TTL задачи 1 ч.

## 10. Эффективность шаблона (ночной цикл)

```
измеряется:  Δx_i     — фактическое изменение драйва в окне [t_start, t_end+lag]
             cost     — потраченные токены

E_T      ← (1 − α)·E_T + α · (−Δx_i / max(cost, cost_min))     α = 0.25
succ_T   ← (1 − α)·succ_T + α · [консумация верифицирована]
n_T      ← n_T + 1
```

Шаблон уходит в архив при `n_T ≥ n_min` и `E_T < E_retire`. Удаления нет — только
архив, иначе история эффективности теряется и цикл начнёт колебаться.

## 11. Ренормализация (ночной цикл)

```
для каждого модулятора и сетпоинта:
    v ← v + λ · (v_temperament − v)         λ = 0.30
```

Один шаг в сутки, коэффициент фиксированный. Единственная защита от многонедельного
дрейфа: внутридневные механизмы такого сноса не видят, потому что он медленнее их τ.

## 12. Отображение аппрейзала в импульсы

Выход L-1 — строгая схема, каждое поле ∈ известном диапазоне:

```
{valence: −2..2, threat: 0..2, novelty: 0..2, social_warmth: −2..2,
 agency_blocked: bool, loss: 0..2}
```

Матрица (амплитуда `a` для формулы §4):

| Условие | Драйв | a |
|---|---|---|
| `threat > 0` | FEAR | +0.30 · threat/2 |
| `agency_blocked` и `valence < 0` | RAGE | +0.35 |
| `novelty > 0` | SEEKING | +0.25 · novelty/2 |
| `loss > 0` | PANIC | +0.30 · loss/2 |
| `social_warmth > 0` | CARE | +0.20 · warmth/2 |
| `social_warmth > 0` | PANIC | −0.40 · warmth/2 |
| `valence > 0` и `threat = 0` | PLAY | +0.15 · valence/2 |

Событие `user_message` дополнительно и **безусловно**:

```
t_last_contact ← t
PANIC:  Δ = −0.60          (контакт восстановлен — прямое гашение сепарации)
```

Невалидная схема на выходе малой модели → все поля в ноль, событие логируется как
`appraisal_invalid`. Отказ сенсора не должен двигать состояние.

---

## 13. Соматические сигналы

Не аффект. Датчики → сома → модуляция гейнов и порогов:

```
temp > 75°C или throttled     → thermal ↑    → ↓ гейн SEEKING/PLAY, ↑ пороги
disk_free < 10% или сервис ↓  → integrity ↓  → CARE-задача, FEAR += 0.15
load / uptime / час суток     → energy       → см. §1.1
сеть недоступна > 5 мин       → PANIC += 0.25, FEAR += 0.20
```

Единственный случай, где железо бьёт прямо в аффект — потеря сети: для этой системы
потеря сети и есть потеря мира.
