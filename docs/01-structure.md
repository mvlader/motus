# MOTUS — структура системы

> *motus animi* (Цицерон) — «движение души». Латинский термин, от которого происходит
> «эмоция». Выбран в пару к Anima/NIMA; заменяется одним `sed`, если не нравится.

MOTUS — слой мотивации и поведенческого управления для бота на stateless-LLM.
Он **не** система памяти и **не** система идентичности: это ортогональный слой,
отвечающий на два вопроса — *чего система сейчас хочет* и *что ей сейчас разрешено*.

---

## 1. Инвариант проекта

**Числа никогда не покидают код. Модель никогда не видит чисел состояния.**

Из этого следуют три жёстких правила, нарушение любого из них разрушает систему:

1. LLM получает только текстовую карточку фиксированного лексикона (≤ бюджета).
2. L-1 использует малую модель как сенсор (`mode: model`, умолчание) — её выход
   ограничен строгой схемой. Отключаемый режим `off` — совсем без оценки текста.
3. Насыщение драйва начисляет код по проверяемому событию, а не по заявлению модели.

## 2. Слои

```
                    ┌─────────────────────────────────────────┐
   события мира ───►│ L-1  APPRAISAL      текст/сигнал → числа │
   железо, время    │      правила + модель как сенсор         │
                    └────────────────┬────────────────────────┘
                                     │ impulses
                    ┌────────────────▼────────────────────────┐
                    │ L0   HOMEOSTAT      чистая математика    │
                    │      драйвы · модуляторы · сома · часы   │
                    └────────────────┬────────────────────────┘
                                     │ state vector
                    ┌────────────────▼────────────────────────┐
                    │ L1   GATEKEEPER     числа → режим+маска  │
                    │      гистерезис · dwell · приоритет      │
                    └────────────────┬────────────────────────┘
                                     │ Gate(capabilities, directives)
                    ┌────────────────▼────────────────────────┐
                    │ L2   VERBALIZER     режим → текст        │
                    │      фикс. лексикон · без чисел · бюджет │
                    └────────────────┬────────────────────────┘
                                     │ Card (≤ 320 симв.)
                    ┌────────────────▼────────────────────────┐
                    │      большая LLM: только формулировки    │
                    └─────────────────────────────────────────┘

   всё, что происходит на каждом слое → JOURNAL (append-only jsonl)
```

| Слой | Модуль | Детерминирован | LLM |
|---|---|---|---|
| L-1 | `appraisal.py` | нет (`mode: model`, умолчание); **да** на отказе сенсора (`model_fallback: lexical`, docs/04) | малая, выход по строгой схеме |
| L0 | `core.py`, `state.py`, `clock.py` | **да, полностью** | нет |
| L1 | `gates.py` | **да, полностью** | нет |
| L2 | `verbalizer.py` | **да, полностью** | нет |
| — | `repertoire.py` | да (выбор), нет (исполнение) | по `cost_tier` |
| — | `journal.py`, `replay.py` | да | нет |

## 3. Состав состояния

### 3.1 Драйвы (системы действия Панксеппа), 6 шт., ∈ [0,1]

| Драйв | Тип | Поведенческий класс |
|---|---|---|
| SEEKING | тонический | исследование, инициатива, новые темы |
| CARE | тонический | проактивная помощь, забота о состоянии пользователя |
| PLAY | тонический | юмор, эксперимент, вариация |
| FEAR | фазический | верификация, хеджирование, отказ от риска |
| RAGE | фазический | резкость, отказ, защита границ |
| PANIC | фазический | восстановление контакта, сепарационный дистресс |

LUST исключён: у бота нет референта. Оставлять его декорацией — вносить шум в
приоритеты и в статистику эффективности.

### 3.2 Усилители A[da], B[ne], C[ht5] — слой глобального усиления, 3 шт., ∈ [0,1]

Три независимых коэффициента усиления, **не эмоции и не нейрохимия**. Буквы A/B/C —
рабочие имена для прозы; в коде это по-прежнему `da`, `ne`, `ht5` — короткие
аналогии с дофамином, норадреналином и серотонином, формально навеянные кубом
Лёвхейма. Реальной нейрохимии тут нет: куб Лёвхейма как научная гипотеза
эмпирически не подтверждён (см. docs/02-terms.md), используется только как источник
размерности (3 независимые оси), а не как таксономия аффектов.

- **A** [`da`] — усиление аппетитивных драйвов, понижает порог действия
- **B** [`ne`] — темп: ускоряет динамику, повышает частоту тиков, обостряет пороги
- **C** [`ht5`] — терпимость: сдвигает пороги вверх, ускоряет спад быстрых драйвов

### 3.3 Сома (тело), 3 шт., ∈ [0,1]

`energy`, `integrity`, `thermal` — интероцепция, не аффект. Не участвует в выборе
режима, только модулирует гейны и пороги. Источник — датчики железа Pi.

### 3.4 Часы

| Часы | Что меряют | Куда входят |
|---|---|---|
| стенные | абсолютное время | циркадный модулятор `energy` |
| контакта | `t − last_contact` | динамический сетпоинт PANIC (сепарация) |
| контекста | `t − last_context` | `freshness`, полосы свежести, гейт на ссылки |

## 4. Демон: что это и зачем

**Демон — это программа, которая постоянно висит в фоне** (юнит systemd), в отличие
от скрипта, запускаемого на каждый запрос. `motusd` — единственный владелец
состояния: он держит вектор в памяти, тикает по таймеру, пишет журнал и снапшот на
диск. Всё остальное обращается к нему по HTTP как к маленькому веб-API на localhost.

**Почему не библиотека, импортируемая в openclaw.** У состояния должен быть ровно
один владелец. openclaw перезапускается, каждая сессия — отдельный процесс. Если
каждая сессия импортирует математику как библиотеку, получится N копий вектора,
которые гонятся друг с другом и расходятся; кто последний записал снапшот — тот и
прав. Плюс тики должны идти и когда сессий нет вообще, иначе время между
разговорами для системы не существует, а это половина смысла проекта.

**Аналогия:** термостат в стене. openclaw спрашивает «какое состояние и что можно»
и получает ответ. Термометром он не владеет и крутить его не может.

### Два слушателя

`motusd` живёт в отдельном Incus-контейнере `motus`, изолированном от openclaw
(развёртывание — `deploy/DEPLOY.md`). Наружу к openclaw торчит только урезанный
набор эндпоинтов, без единого числа; полный API — на локальном unix-сокете внутри
контейнера.

| Метод | Путь | Публичный (openclaw) | Назначение |
|---|---|:---:|---|
| `GET` | `/state/card` | ✓ | карточка (текст, без чисел) + capability mask |
| `POST` | `/event` | ✓ | событие (сообщение, датчик, ошибка инструмента, сеть) |
| `GET` | `/task/next` | ✓ | задача из репертуара доминирующего драйва (Tier 1) |
| `POST` | `/consummation` | ✓ | засчитать выполнение задачи (проверяемый факт) |
| `GET` | `/initiate/pending` | ✓ | есть ли решённая проактивная инициация к доставке (Tier 2), только после `INITIATE_MIN_SILENCE_S` тишины |
| `POST` | `/refund` | ✓ | вернуть токен, если инициация не состоялась |
| `POST` | `/llm_call` | ✓ | зарегистрировать вызов модели |
| `GET` | `/health` | ✓ | жив ли, версия, seq |
| `GET` | `/state/raw` | — | сырые числа — только оператору, не в промпт |
| `GET` | `/journal/tail?n=` | — | хвост журнала |
| `POST` | `/tick` / `/sleep` | — | форс-тик / ночной цикл (демон делает и сам) |

На публичном слушателе `/state/card` вдобавок вырезает из `gate` поля `activation`
и `somatic_flags` — это числа. Порт **18790** (у openclaw gateway — 18789).

### Интеграция с openclaw

Плагин `deploy/openclaw-plugin/` на хуке `before_prompt_build`: шлёт текст
сообщения в `POST /event`, забирает `GET /state/card`, дописывает `card.text` в
конец промпта и (опц.) сужает инструменты хода по `gate.allowed_tools`. Контракт
эндпоинтов — `deploy/openclaw-hook.md`. Тик и ночной цикл демон крутит сам, cron
не нужен.

## 5. Иерархия пробуждений (heartbeat)

| Уровень | Условие | Кто работает | Стоимость |
|---|---|---|---|
| Tier 0 | каждые `tick_s` (адаптивно 45 с … 10 мин) | только математика | 0 |
| Tier 1 | `dominant ≥ θ_task` и гейт разрешает | **задача из репертуара**, локальная модель | ~0 |
| Tier 2 | `dominant ≥ θ_act` и `may_initiate` и бюджет | большая модель, право говорить | $ |
| Сон | раз в 24 ч при низкой активации и пустой очереди | реплей + курирование + возврат к темпераменту | ~0 |

Интервал Tier 0 растёт экспоненциально при низкой активации и отсутствии событий
(«сон»); поскольку вся динамика построена на экспонентах от Δt, редкие тики дают
тот же результат, что частые — компенсация не нужна.

## 6. Задачи как консумматорные акты

Драйв нельзя погасить разговором о драйве. У каждого драйва есть репертуар шаблонов
задач; выполнение задачи с **проверяемым** результатом гасит драйв.

**Разделение полномочий — три уровня, граница жёсткая:**

| Уровень | Содержимое | Кто правит |
|---|---|---|
| Ядро драйва | определение, критерий насыщения | никто, константа в коде |
| Математика | гейны, пороги, τ, эффективность шаблонов | только код, по измерениям |
| Репертуар | шаблоны, формулировки, `rationale` | модель, ночью, в пределах квоты |

**Какой драйв доминирует — решает математика. Какую задачу взять внутри драйва —
решает модель.** Дать модели выбирать драйв — значит превратить гомеостат в декорацию.

| Драйв | Задача | Консумматорный акт | Гейткипер |
|---|---|---|---|
| SEEKING | исследовать непрочитанное, размотать нитку из памяти | запись памяти с новизной > θ | — |
| CARE | заметить сломанное, подготовить починку, проверить бэкапы | артефакт в очередь на ревью | не отправляет |
| PLAY | написать, сделать вариацию, эксперимент | артефакт создан, польза **не требуется** | блок при любом аверсивном |
| FEAR | верификация, прогон проверок, бэкап, откат | проверка прошла | необратимое запрещено |
| PANIC | перечитать диалог, собрать re-entry записку | handoff-артефакт готов | исходящие запрещены |
| RAGE | — | — | репертуара нет |

**Абсолютное правило: фоновая задача не отправляет ничего наружу. Никогда.**
Единственный путь к исходящему сообщению — Tier 2 с открытым `may_initiate`.

## 7. Ночной цикл (24 ч)

1. **Реплей и оценка** — прочитать журнал дня, посчитать, какие шаблоны какие драйвы
   реально гасили и какой ценой; обновить `efficacy`. Делает код.
2. **Курирование репертуара** — показать модели измерения (`Repertoire.efficacy_report()`),
   дать переписать `prompt`/`rationale`, добавить/архивировать шаблоны в пределах
   квоты (`motus/curator.py`, реализовано). Модель предлагает — структурированным
   ответом по жёсткой схеме, тем же приёмом, что L-1; код проверяет и применяет
   (`Repertoire.apply_edits()`), ничего не принимая на веру: ядро существующего
   шаблона (drive/consummation/preconditions) правкой "rewrite" не тронуть — этих
   полей в её схеме просто нет; для нового шаблона drive/consummation_type/
   preconditions ограничены заранее заданным словарём (fail-closed). Вызывает
   `Service.run_curation()` в `daemon.py`, только после успешного (не отложенного)
   сна — у Engine/Homeostat сетевого доступа нет и не будет. Отказ модели — цикл
   просто пропускается, репертуар как был. Выключено по умолчанию
   (`curation.enabled: false`) — новая возможность, включать осознанно.
3. **Ренормализация** — стянуть модуляторы и сетпоинты к базовому темпераменту.
   Единственная защита от многонедельного дрейфа в вырожденный угол.
4. **Консолидация памяти** — дневной лог → кураторские слои (штатный ритуал openclaw,
   не переписываем).

Условия запуска: низкая активация **и** пустая очередь пользователя. Возбуждённое
состояние откладывает сон, и сам факт отложенного сна логируется — это индикатор
незатухающей петли. Цикл прерываем: пришёл пользователь — доигрывается позже.

## 8. Журнал и воспроизводимость

Append-only JSONL, одна запись на событие.

| Тип | Когда пишется | Что несёт |
|---|---|---|
| `boot` | старт демона | версия схемы, смещение часового пояса |
| `tick` | каждый тик | Δt, уровень, активация, arousal, **гейт целиком**, снимок вектора |
| `event` | событие мира | вид и payload — этого достаточно для реплея |
| `impulse` | каждый импульс | драйв, амплитуда, ключ габитуации, фактическое приращение |
| `gate_change` | смена режима | откуда, куда, снимок |
| `card` | изменение текста карточки | текст, режим, сколько сегментов обрезано |
| `llm_call` | вызов языковой модели | модель, назначение, токены, шаблон |
| `task` | выдача задачи | шаблон, драйв, инструменты, срок |
| `consummation` | засчитанное выполнение | шаблон, verified, Δ драйва, стоимость |
| `sleep` | ночной цикл или его отсрочка | причина, число шаблонов |
| `curation` | шаг 2 ночного цикла (если `curation.enabled`) | сколько предложено/применено/отклонено, с причиной |
| `appraisal_invalid` | модель L-1 (`mode: model`) реально отказала на непустом тексте | сколько символов было |
| `error` | сбой тика, консумация без задачи, битый/нечисловой снапшот, самосброс NaN-вектора | что именно (`what`) |

Каждая запись несёт `seq`, `t`, `kind`, `payload`; `tick` и ключевые записи — ещё и
полный снимок вектора. Время пишется **без округления**: реплей должен попадать в те
же моменты, иначе детерминизм теряется на round-trip через JSON.
Из журнала событий состояние восстанавливается **побитово** (`replay.py`) — это и
регрессионный тест, и единственный способ ответить на вопрос «почему она это сказала».

Ротация посуточная, `var/journal/YYYY-MM-DD.jsonl`.

## 9. Критерий качества

Не экспертная оценка текстов (см. разбор ACAS — такой тест не отличает управляемую
систему от модели, отыгрывающей описание состояния), а **поведенческий булев тест**:

> прогнать фиксированный лог событий через ядро и проверить, что при закрытом гейте
> инициации исходящих сообщений ноль — ни разу, ни при какой формулировке.

Воспроизводимо, не требует судьи, ловит регрессии.
