# Подключение к OpenClaw

MOTUS живёт в **отдельном Incus-контейнере `motus`** (не в grach). Incus proxy
device форвардит его публичный API в grach как `127.0.0.1:18790`, так что для
хуков openclaw это обычный локальный HTTP. Что видно на этом порту:

| Эндпоинт | |
|---|---|
| `GET /state/card` | карточка + маска полномочий (без единого числа) |
| `POST /event` | событие мира (сообщение, ошибка инструмента, потеря сети) |
| `GET /task/next` | взять фоновую задачу из репертуара |
| `POST /consummation` | засчитать выполнение задачи (проверяемый факт) |
| `POST /refund` | вернуть токен, если инициация не состоялась |
| `POST /llm_call` | зарегистрировать вызов модели (для учёта стоимости) |
| `GET /health` | жив ли |

`GET /state/raw`, журнал, `/tick`, `/sleep` **openclaw недоступны** (404) — они
только на unix-сокете внутри контейнера `motus`. Сырые числа драйвов openclaw не
видит вообще: ни в файле, ни по HTTP.

Три точки интеграции. Ни одна не требует правок в самом MOTUS.

## 1. Карточка в промпт (хук перед сборкой)

```bash
RESP=$(curl -s --max-time 2 127.0.0.1:18790/state/card)
CARD=$(echo "$RESP" | python3 -c 'import sys,json;print(json.load(sys.stdin)["card"]["text"])' 2>/dev/null)
```

Вставить `$CARD` **в конец** системного блока — рецентность важна. Если демон не
ответил за 2 с, промпт собирается **без карточки**: MOTUS не должен быть единой
точкой отказа бота.

Вместе с карточкой приходит `gate` — это и есть «зубы». Применять до генерации:

```json
"gate": {
  "regime": "FEAR",
  "may_initiate": false,
  "max_tokens": 400,
  "allowed_tools": ["read", "memory", "exec"],
  "forbidden": ["irreversible", "promises"],
  "context_band": "aging"
}
```

- `may_initiate: false` → бот не имеет права слать сообщение сам (Tier 2 закрыт).
- `allowed_tools` / `forbidden` → урезать набор инструментов сессии.
- `max_tokens` → лимит длины ответа.
- `regime` (имя, не число) → ветка поведения, если хочешь.

Пока хук просто вставляет `card.text` и не смотрит на `gate` — MOTUS работает,
но ничего не ограничивает.

## 2. События после ответа

Прислать сырой текст, MOTUS сам оценит его словарём (`appraisal.mode: lexical`,
~1 мс — не блокирует):

```bash
curl -s -XPOST --max-time 2 127.0.0.1:18790/event \
  -d '{"kind":"user_message","payload":{"text":"наконец-то заработало, спасибо!"}}'
```

Текст обрабатывается и **сразу выбрасывается** — в журнал уходят только шесть
маленьких чисел, не содержание. Если оценка не удалась — событие всё равно
проходит (сепарация гасится безусловно), просто без оценки содержания.

Другие полезные события: `{"kind":"tool_error","payload":{"tool":"...","blocking":true}}`,
`{"kind":"net_down"}` / `{"kind":"net_up"}`, `{"kind":"assistant_message"}` (просто
двигает часы контекста).

Альтернатива — прислать готовую оценку самому (если openclaw хочет считать её
своей моделью):

```bash
curl -s -XPOST 127.0.0.1:18790/event \
  -d '{"kind":"user_message","payload":{"appraisal":{"novelty":1,"social_warmth":1}}}'
```

`text` и готовый `appraisal` в одном payload не смешивать: если `appraisal` есть,
`text` игнорируется.

## 3. Фон

Демон тикает и запускает ночной цикл сам — cron для `/tick`/`/sleep` не нужен
(да и эти эндпоинты openclaw недоступны). Датчик железа — `motus-somatic.timer`
внутри grach (раз в 5 мин, шлёт температуру/диск/живость openclaw в `/event`),
уже установлен.

## Изоляция (что openclaw НЕ может)

- читать код MOTUS и `state.json` — они в другом контейнере;
- дёргать `/state/raw`, журнал, `/tick`, `/sleep` — 404;
- получить числа драйвов — из карточки они вырезаны (`activation`, `somatic_flags`);
- `sudo` внутрь `motus` — это отдельный контейнер.

Инспекция состояния (для тебя): `incus exec motus -- curl -s --unix-socket
/run/motusd/adm.sock http://x/state/raw`.
