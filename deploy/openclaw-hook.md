# Подключение к OpenClaw

Три точки. Ни одна не требует правок в самом MOTUS.

`motusd` работает **внутри того же Incus-контейнера `grach`**, что и openclaw,
поэтому все обращения ниже идут на `127.0.0.1:18790` напрямую — без Incus-прокси
и без докеровского `host.docker.internal` (Docker в этой системе нет вообще).

## 1. Карточка в промпт (хук перед сборкой)

```bash
CARD=$(curl -s --max-time 2 localhost:18790/state/card | python3 -c \
  'import sys,json;print(json.load(sys.stdin)["card"]["text"])' 2>/dev/null)
```

Вставить `$CARD` **в конец** системного блока — рецентность важна. Если демон не
ответил за две секунды, промпт собирается без карточки: MOTUS не должен быть
единой точкой отказа бота.

## 2. События после ответа

Самый простой вариант — прислать сырой текст, MOTUS сам его оценит своим L-1
(см. [docs/04-model-l1.md](../docs/04-model-l1.md)):

```bash
curl -s -XPOST --max-time 2 localhost:18790/event \
  -d '{"kind":"user_message","payload":{"text":"наконец-то заработало, спасибо!"}}'
```

Текст обрабатывается и **сразу выбрасывается** — в журнал MOTUS уходят только шесть
маленьких чисел, не содержание сообщения. Если оценка не удалась — событие всё
равно проходит (сепарация гасится безусловно), просто без оценки содержания.

> По умолчанию (`appraisal.mode: lexical`) оценка словарём — ~1 мс, вызов не
> блокирует. **Если переключить на `mode: model`** — вызов блокируется на всё
> время инференса (~10 с на Pi 5, сенсор в `submit_event` синхронный): тогда шли
> его в фоне (`curl ... &`) или через очередь, он уходит уже *после* ответа
> пользователю.

Альтернатива — прислать уже готовую оценку самому (например, если openclaw хочет
считать её своей моделью, а не через L-1 MOTUS):

```bash
curl -s -XPOST localhost:18790/event \
  -d '{"kind":"user_message","payload":{"appraisal":{"novelty":1,"social_warmth":1}}}'
```

`text` и готовый `appraisal` в одном payload не смешивать: если `appraisal` уже
есть, MOTUS его не пересчитывает и `text` просто игнорируется. Невалидный
ответ сенсора — не беда: схема падает в нули, состояние не двигается.

## 3. Cron / таймеры

| Что | Расписание | Зачем |
|---|---|---|
| `POST /tick` | каждые 5 мин | подстраховка, если тикер демона встал |
| `POST /sleep` | раз в сутки, ночью | ночной цикл (сам проверит активацию) |
| `somatic_probe.py` | каждые 5 мин | температура/троттлинг/диск/живость openclaw → соматика |

Тикать основным циклом cron не нужно — демон тикает сам и сам выбирает интервал.
Датчик железа уже оформлен: `deploy/motus-somatic.{service,timer}` (systemd-таймер,
внутри `grach`), `sudo systemctl enable --now motus-somatic.timer`.

## Ограничение доступа

Демон слушает `127.0.0.1`. openclaw живёт в том же контейнере `grach`, поэтому
достаёт его на `127.0.0.1:18790` без проброса. Наружу контейнера порт 18790 не
публикуется (в отличие от `ui`-порта openclaw 18789) — MOTUS доступен только
изнутри `grach`.
