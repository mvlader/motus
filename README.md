# MOTUS

Слой мотивации и поведенческого управления для бота на stateless-LLM.
Числовые шкалы потребностей и систем действия по Панксеппу, жёсткие логические шлюзы,
фоновый heartbeat и явная модель времени.

**Это не система памяти и не система идентичности.** MOTUS ортогонален им: он отвечает
на вопросы «чего система сейчас хочет» и «что ей сейчас разрешено», а не «что она
помнит» и «кто она». С Anima-подобным слоем памяти стыкуется в двух швах: общая ось
времени и (опционально) аффективный тег на записях.

## Инвариант

> Числа никогда не покидают код. Модель никогда не видит чисел состояния.

Модель получает только текстовую карточку фиксированного лексикона и выбирает
формулировки. Ни одной цифры — проверяется тестом `test_no_digits_ever`.

```
последний обмен — несколько часов назад; нить разговора уже подостыла — уточняй,
если ссылаешься на неё. Состояние: тянет разобраться в чём-то новом.
Можно предложить тему самому — одну, не список.
```

## Запуск

Локально (один общий TCP-слушатель со всеми эндпоинтами — для разработки и тестов):

```bash
python3 -m motus.daemon --port 18790
curl -s localhost:18790/state/card | python3 -m json.tool
```

На Pi — отдельный изолированный контейнер + плагин openclaw: см. [deploy/DEPLOY.md](deploy/DEPLOY.md).

Зависимостей нет — только стандартная библиотека Python 3.11+. Это осознанно:
система должна переживать `pip` на Raspberry Pi и запускаться из systemd без venv.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

## Калибровка

```bash
python3 tools/simulate.py --hours 72 --scenario silence
```

Параметров около сорока; вслепую их не настроить. Реплей-стенд прогоняет сутки за
миллисекунды — калибруй по графикам, а не подбором.

## Конфигуратор

```bash
python3 tools/motusctl.py
```

Меню в терминале, запускается на хосте с репозиторием. Правит `config/` в git и
раскладывает в деплой (настройка «запуск через» — контейнер incus; пусто — локально;
хранится в `~/.config/motusctl/settings.json`). Поток: validate → бэкап → атомарная
запись → сверка деплоя с git → push → предложение рестарта. Там же реплей-стенд
(молчание, поток событий, sweep параметра, прогон журнала), песочница — второй
`motusd` на свежем порту — и настройки плагина openclaw. `state.json` боевого
демона меню не пишет никогда.

## Что уже работает (v0.1)

- L0 гомеостат: 6 драйвов, 3 модулятора, сома, три часа
- L1 гейткиперы: гистерезис, время удержания, приоритет, маска разрешений
- L2 генератор карточки: фиксированный словарь, бюджет, запрет цифр
- L-1 оценщик сигнала: правила событий + оценка текста моделью (`mode: model`,
  умолчание — gemma-4 E4B на ПК по LAN через ollama, лучшая точность). ПК не
  всегда включён и платить за облако ради L-1 не хочется — при отказе сенсора
  `model_fallback: lexical` откатывает на детерминированный словарь
  (`lexicon_l1.py`, бесплатно, локально, один язык — русский) вместо тишины —
  [docs/04-model-l1.md](docs/04-model-l1.md)
- Бюджет инициаций, рефрактерность, штраф за молчание
- Репертуар задач и учёт эффективности
- Журнал append-only и реплей с проверкой детерминизма
- Демон: два слушателя (публичный без чисел + админ-сокет)
- Датчик железа Pi 5: `deploy/somatic_probe.py` + systemd-таймер шлют температуру,
  свободный диск и живость openclaw в `somatic_update()`
- Защита от NaN/±Inf/нулевых τ в конфиге и снапшоте
- **Исполнитель консумматорных актов (Tier 1)** — не таск-раннер для
  пользователя, то, чем система занимается сама с собой в тишине:
  `deploy/tier1_executor.py` + таймер `motus-tier1` в grach: `GET /task/next` →
  изолированный `openclaw agent exec` (без каналов) → проверка кодом →
  `POST /consummation`. Репертуар (`config/repertoire.json`) переписан под это —
  часть актов (`consummation.type: "reflection"`) не требует артефакта вовсе,
  верифицируется только тем, что ход состоялся
- **Доставка проактивных сообщений (Tier 2)** — `deploy/tier2_executor.py` +
  таймер `motus-tier2`: `GET /initiate/pending` (решено только после тишины
  дольше `INITIATE_MIN_SILENCE_S`) → `openclaw agent --deliver` → `/refund` при
  сбое канала. `budget.initiation_enabled` по умолчанию `false` — исполнитель
  написан, но включать только осознанно, когда получатель настроен
- **Плагин openclaw жёстко enforces `max_tokens` и `forbidden: outbound`** —
  хук `message_sending` (при `config.applyGate: true`): режет длину на самой
  отправке, целиком отменяет сообщение в режимах вроде RAGE. Остальные
  `forbidden` (`irreversible`, `new_topics`…) по-прежнему просьба в карточке,
  не хук — так задумано (L2: директивы, не механический запрет)
- **Курирование репертуара моделью** (ночной цикл, шаг 2) — `motus/curator.py`:
  модель предлагает правки `prompt`/`rationale`/новые шаблоны структурированным
  ответом, `Repertoire.apply_edits()` проверяет и применяет (ядро шаблона
  трогать нельзя, drive/consummation_type/preconditions нового шаблона —
  только из заданного словаря, квота 3 правки/ночь). Персистентно
  (`var/repertoire.json`, переживает рестарт). Выключено по умолчанию
  (`curation.enabled: false`)
- Демон ловит и логирует необработанные ошибки в обработчиках запросов (раньше
  падали молча в stderr, теперь — `error` в журнал + 500 клиенту); прогрев
  L-1-сенсора при полном отказе тоже теперь пишет в журнал, не молчит
- **Задеплоено на Pi**: изолированный контейнер `motus` + плагин openclaw
  ([deploy/DEPLOY.md](deploy/DEPLOY.md), [deploy/openclaw-plugin/](deploy/openclaw-plugin/))
  — но Tier 1/Tier 2/новый хук плагина/курирование пока только в репозитории, не раскатаны
- 126 тестов, включая поведенческий критерий «при закрытом гейте инициаций ноль»

## Чего ещё нет

- **Новизна через эмбеддинги** для SEEKING — критерий консумации описан в
  формулах, но сейчас нет замены (по примеру L-1 напрашивается детерминированная:
  шинглы/overlap — требует локального эмбеддера иначе).
- **Аффективный тег на записях памяти** — решение отложено намеренно.
- **Пост-проверка ответа модели** — пятое анти-дрейфовое правило: дешёвый чек
  «нарушены ли директивы» с регенерацией при нарушении. Без него состояние
  влияет на промпт, но не проверяется на выходе.
- **Фильтр на запись в память** — правило 2 ниже пока действует как соглашение,
  а не как код: ничто технически не мешает записать «мне было тревожно» в
  дневной файл.
- **Субъективное время** (`Δt_subj = Δt·(1 + k·A)`) — описано в формулах §1.3,
  в коде и конфиге отсутствует.

## Граница самомодификации

| Уровень | Кто правит |
|---|---|
| Ядро драйва: определение, критерий насыщения | никто, константа в коде |
| Математика: гейны, пороги, τ, эффективность | только код, по измерениям |
| Репертуар: шаблоны, формулировки, rationale | модель, ночью, в пределах квоты |

Какой драйв доминирует — решает математика. Какую задачу взять внутри драйва —
решает модель.

## Два правила, которые нельзя нарушать

1. **Фоновая задача не отправляет ничего наружу.** Никогда. Единственный путь к
   исходящему сообщению — Tier 2 с открытым `may_initiate`. Иначе гейты обходятся
   через репертуар, и вся конструкция бессмысленна.
2. **Вывод генератора карточки не попадает в память как текст.** Если бот запишет
   «мне было тревожно», в следующей сессии это приедет в стартовый контекст как факт
   о себе и будет отыгрываться поверх математики — неконтролируемый контур,
   обходящий ядро, с задержкой в сутки.
