# MOTUS

Слой мотивации и поведенческого управления для бота на stateless-LLM.
Числовые шкалы потребностей и систем действия по Панксеппу, жёсткие логические шлюзы,
фоновый heartbeat и явная модель времени.

**Это не система памяти и не система идентичности.** MOTUS ортогонален им: он отвечает
на вопросы «чего система сейчас хочет» и «что ей сейчас разрешено», а не «что она
помнит» и «кто она». С Anima-подобным слоем памяти стыкуется в двух швах: общая ось
времени и (опционально) аффективный тег на записях.

## Инвариант

> Числа никогда не покидают код. Модель никогда не видит чисел состояния.

Модель получает только текстовую карточку фиксированного лексикона и выбирает
формулировки. Ни одной цифры — проверяется тестом `test_no_digits_ever`.

```
последний обмен — несколько часов назад; нить разговора уже подостыла — уточняй,
если ссылаешься на неё. Состояние: тянет разобраться в чём-то новом.
Можно предложить тему самому — одну, не список.
```

## Запуск

Локально (один общий TCP-слушатель со всеми эндпоинтами — для разработки и тестов):

```bash
python3 -m motus.daemon --port 18790
curl -s localhost:18790/state/card | python3 -m json.tool
```

На Pi — отдельный изолированный контейнер + плагин openclaw: см. [deploy/DEPLOY.md](deploy/DEPLOY.md).

Зависимостей нет — только стандартная библиотека Python 3.11+. Это осознанно:
система должна переживать `pip` на Raspberry Pi и запускаться из systemd без venv.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

## Калибровка

```bash
python3 tools/simulate.py --hours 72 --scenario silence
```

Параметров около сорока; вслепую их не настроить. Реплей-стенд прогоняет сутки за
миллисекунды — калибруй по графикам, а не подбором. То же с таблицами «значение →
поведение» — в конфигураторе, раздел «Тесты драйвов» (например, молчание с 20:00:
`θ_act = 1.1` → первая инициация через 3 ч 30 мин, `1.25` → ни разу за сутки).

## Конфигуратор

```bash
python3 tools/motusctl.py
```

Меню в терминале, запускается на хосте с репозиторием. Правит `config/` в git и
раскладывает в деплой (настройка «запуск через» — контейнер incus; пусто — локально;
хранится в `~/.config/motusctl/settings.json`). Поток: validate → бэкап → атомарная
запись → сверка деплоя с git → push → предложение рестарта. Там же статус агента,
тесты драйвов (молчание, поток событий, sweep параметра, прогон журнала) и
настройки плагина OpenClaw. `state.json` демона меню не пишет никогда.

## Что уже работает (v0.1)

Всё перечисленное задеплоено на Pi 5 (контейнеры `motus` и `grach`, см.
[deploy/DEPLOY.md](deploy/DEPLOY.md)); 216 тестов.

**Ядро**
- L0 гомеостат: 6 драйвов, 3 модулятора, сома (`energy`, `integrity`, `thermal`,
  `limit`), три часа; часовой пояс оператора — `clock.timezone`
- L1 гейткиперы: гистерезис, время удержания, приоритет, маска разрешений
- L2 генератор карточки: фиксированный словарь (`ru`/`en`, `verbalizer.lexicon`),
  бюджет символов, запрет цифр
- L-1 оценщик сигнала: правила событий + оценка текста моделью — сейчас
  `claude-sonnet-5` через `claude -p` на подписке Claude Code, без инструментов;
  при отказе — детерминированный словарь (`model_fallback: lexical`) вместо
  тишины — [docs/04-model-l1.md](docs/04-model-l1.md)
- Бюджет инициаций, рефрактерность, штраф за молчание, тихие часы оператора
  (`budget.quiet_hours`, на ответы не влияют)
- Репертуар актов и учёт эффективности; ночное **самокурирование** репертуара
  моделью (`motus/curator.py`, включено 2026-09-15, `claude-sonnet-5`): модель
  предлагает до 3 правок за ночь, `Repertoire.apply_edits()` проверяет каждую
  кодом, ядро шаблона тронуть нельзя
- Журнал append-only и **точный реплей**: запись `boot` несёт полный вектор, в
  журнал попадает всё, что меняет состояние (сон, refund, протухание задач,
  подмена репертуара), поэтому прогон воспроизводит демон побитово и через
  рестарты. Журналы до 2026-09-15 так не воспроизводятся (`legacy_boots`)
- Защита от NaN/±Inf/нулевых τ в конфиге и снапшоте; необработанные ошибки
  обработчиков — `error` в журнал + 500 клиенту

**Демон и окружение**
- Демон: два слушателя (публичный без чисел + админ-сокет)
- Датчик железа Pi 5 (`deploy/somatic_probe.py`, раз в 5 мин): температура,
  свободный диск, живость openclaw
- **Датчик 5-часового лимита Claude** (`deploy/limit_probe.py`, раз в 10 мин):
  сома `limit`, импульс FEAR на резкий рост, после 70 % — плавное урезание
  `max_tokens`, после 95 % — ход не доходит до модели, пользователь получает
  готовый текст «отвечу примерно через N мин» (хук `before_agent_run`)
- **Tier 1 — консумматорные акты** (`deploy/tier1_executor.py`, таймер в grach):
  `GET /task/next` → один ход `openclaw agent exec` с узким exec-конфигом (без
  каналов отправки и без веба) → проверка факта кодом → `POST /consummation`.
  Часть актов (`consummation.type: "reflection"`) не требует артефакта
- **Tier 2 — проактивные сообщения** (`deploy/tier2_executor.py`): включено
  (`budget.initiation_enabled: true` с 2026-09-12), `GET /initiate/pending` →
  `openclaw agent --deliver` → `/refund` при сбое канала
- Плагин openclaw: карточка в промпт, события в MOTUS, блок хода на исчерпанном
  лимите; при `applyGate: true` — жёсткое сужение инструментов, отмена отправки
  при `forbidden: outbound` (только RAGE) и обрезка под `max_tokens`. Сейчас
  `applyGate: false`

**Конфигуратор** — `tools/motusctl.py`, см. выше.

## Чего ещё нет

- **Сетевой выход Tier 1 через `exec`.** Веб-инструменты из exec-конфига убраны,
  но оболочка (`curl`) по-прежнему может ходить в сеть; изоляция на уровне
  systemd в непривилегированном контейнере `grach` не работает.
- **`POST /event` ждёт оценку L-1.** Лок демона больше не держится на время
  вызова модели, но сам ответ плагину приходит только после оценки (~2–3 с
  на Claude). Асинхронная отправка события — открытый пункт.
- **Пороги реакции на лимит Claude** (`LIMIT_SOFT`/`LIMIT_HARD`) захардкожены в
  `gates.py`, не в конфиге.
- **Новизна через эмбеддинги** для SEEKING — критерий консумации описан в
  формулах, но сейчас нет замены (по примеру L-1 напрашивается детерминированная:
  шинглы/overlap — требует локального эмбеддера иначе).
- **Аффективный тег на записях памяти** — решение отложено намеренно.
- **Пост-проверка ответа модели** — пятое анти-дрейфовое правило: дешёвый чек
  «нарушены ли директивы» с регенерацией при нарушении. Без него состояние
  влияет на промпт, но не проверяется на выходе.
- **Фильтр на запись в память** — правило 2 ниже пока действует как соглашение,
  а не как код: ничто технически не мешает записать «мне было тревожно» в
  дневной файл.
- **Субъективное время** (`Δt_subj = Δt·(1 + k·A)`) — описано в формулах §1.3,
  в коде и конфиге отсутствует.

## Граница самомодификации

| Уровень | Кто правит |
|---|---|
| Ядро драйва: определение, критерий насыщения | никто, константа в коде |
| Математика: гейны, пороги, τ, эффективность | только код, по измерениям |
| Репертуар: шаблоны, формулировки, rationale | модель, ночью, в пределах квоты |

Какой драйв доминирует — решает математика. Какую задачу взять внутри драйва —
решает модель.

## Два правила, которые нельзя нарушать

1. **Фоновая задача не отправляет ничего наружу.** Никогда. Единственный путь к
   исходящему сообщению — Tier 2 с открытым `may_initiate`. Иначе гейты обходятся
   через репертуар, и вся конструкция бессмысленна.
2. **Вывод генератора карточки не попадает в память как текст.** Если бот запишет
   «мне было тревожно», в следующей сессии это приедет в стартовый контекст как факт
   о себе и будет отыгрываться поверх математики — неконтролируемый контур,
   обходящий ядро, с задержкой в сутки.
